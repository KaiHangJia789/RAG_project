## 二、结论

### 1. 切分策略对最终生成质量影响有限（< 0.05）

四个策略的判官指标（Faithfulness / Answer Relevance / Context Precision）差异都在 5% 以内。这说明**在这个结构化良好的技术文档语料上，切分策略不是生成质量的主导因素** —— 模型能够从不同切分粒度中提取出相近的语义。

这本身是一个有价值的发现：当语料结构清晰、问题与文档有明确对应关系时，**不必在切分策略上过度优化**，把精力投向检索排序和拒答边界更划算。

### 2. paragraph 的检索排序最好

零成本检索指标里，paragraph 的 MRR 最高（0.980）且 source precision 最高（0.472）。

解释：paragraph 以段落为界，块边界与文档的自然结构对齐，检索时「命中标注来源的排名」更靠前。而 fixed_size 和 sentence 在机械边界处把相邻内容切开了，导致排名略有下降。

### 3. 误拒率是当前最该优先解决的问题

| 策略 | 误拒题 |
|---|---|
| splitter | q040 |
| sentence | q011, q020, q040, q044 |
| fixed_size | q050 |
| paragraph | q011, q024 |

**根因分析**（抽查 q020「扫描件 PDF 解析静默失败」）：

检索 top1 命中的是「重复 ingest 冲突」块（同一篇文档的相邻章节），而非「扫描件静默失败」块。LLM 看到的上下文里没有答案 → 触发拒答。

这是**生成层拒答过严**与**检索 top 块未命中答案**叠加的结果，不是阈值层的错（本批 min_score=0 无阈值过滤）。sentence 误拒 4 道、其他策略 1-2 道，说明 sentence 在「答案位于相邻块交界」的边界题上更脆弱 —— 它没有 overlap，而 splitter 有 200 字 overlap。

**改进方向**（第 11 周候选）：
1. 提高 `final_k`（5 → 8），让答案块有更大机会进入上下文
2. 引入 rerank 模型对检索结果重排序
3. 放松 `rag_context_cited` 的拒答指令（当前过于绝对）
4. 为 sentence 加 overlap

### 4. 幻觉率整体很低（0-4%）

四个策略的幻觉率都在 5% 以下，sentence 甚至为 0。说明 `rag_context_cited` 的「仅根据上下文回答」约束有效。

## 三、方法论说明

### 判官批次漂移（本次评测暴露的真实问题）

`sentence` 策略首次评测（9-13）得到 Answer Relevance 0.933 / Context Precision 0.806，与另外三个策略（9-15）差距明显。重跑后（同批次）恢复为 0.987 / 0.967。

**结论：不同批次的判官给分存在系统性漂移。** 对比不同配置时必须**同批次跑完**，否则会把判官漂移误读成配置差异。这正是文档里「换判官 = 历史数字作废」的更隐蔽版本——判官没换，但批次不同也会漂移。

### Hit Rate / MRR 的语义修正

初版实现用「答案**引用**的文档」计算 Hit Rate / MRR，混入了「LLM 是否引用」这个变量（sentence 重跑前后 Hit Rate 从 0.98 漂到 0.96，就是因为 LLM 引用的文档变了）。

已修正为用「**检索命中**的文档」（`RagAnswer.retrieved_docs`），这才是纯检索指标。修正后 Hit Rate 稳定为 1.0（top_k=5 总能命中标注来源）。

## 四、复现

```bash
# 1. 构建全部策略索引
python scripts/build_index.py --all --verify

# 2. 同批次跑四个策略（判官缓存会加速）
for s in splitter sentence fixed_size paragraph; do
  python scripts/run_rag_eval.py --strategy $s
done

```
