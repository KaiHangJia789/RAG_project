# 基础 RAG vs Agentic RAG — A/B 对比报告

- **A 组**（基线）：`ab_basic` — 60 题
- **B 组**（实验）：`ab_agent` — 60 题
- 同一评测集、同一索引、同一判官缓存

> **公平性说明**：Agent 模式每题会多调用若干次 LLM（查询分类、相关性评分、查询重写、工具轮），所以延迟与 token 天然更高。**直接比绝对值意义不大**，有意义的是各质量指标的差异，以及「同等质量下的额外成本」。

## 四、结论

### 实测结论

**Agent 模式在"忠实度"上更强，但代价是延迟 3 倍、误拒率翻倍。**

| 维度 | A 基础 RAG | B Agentic | 变化 | 解读 |
|---|---|---|---|---|
| Faithfulness | 0.9888 | **0.9976** | +0.0088 ✅ | 提升但两者都接近上限（天花板效应） |
| 幻觉率 | 8.33% | **2.17%** | −6.16pp ✅ | **最显著的改善**，接近 4 倍降幅 |
| Hit Rate | 0.9800 | **1.0000** | +0.0200 ✅ | 相关性评分+重写循环确实提升了召回 |
| MRR | 0.9450 | 0.9517 | +0.0067 ✅ | 排序质量小幅提升 |
| Context Precision（来源） | 0.3847 | 0.4030 | +0.0183 ✅ | 一致的小幅提升 |
| Answer Relevance | 0.9813 | 0.9804 | −0.0009 — | 基本持平 |
| **误拒率** | 4.00% | **8.00%** | **翻倍** ⚠️ | **最需要关注的回退** |
| **平均延迟** | 972 ms | **2827 ms** | **2.9×** ⚠️ | 多轮 LLM 调用的直接代价 |

### 三个值得深挖的发现

**1. 幻觉率的改善最实在（8.33% → 2.17%）**

这是 Agent 模式最有价值的收益。原因推测：`finalize` 节点用标准引用管线
重新生成答案，把 `rag_context_cited` 的「仅根据上下文作答」约束重新施加了一遍。
基础 RAG 虽然也用了同一个 prompt，但它只有一次机会；Agent 在生成前多了一层
相关信息收集，上下文质量更高。

**2. 误拒率翻倍是个真问题（4% → 8%）**

具体多拒了 q044 和 q046：

```
ab_basic: 误拒 ['q011', 'q040']
ab_agent: 误拒 ['q011', 'q040', 'q044', 'q046']
```

根因是 Agent 链路多了一层「相关性评分」，而评分节点在拿不准时倾向给低分，
触发重写；重写 2 次仍不达标就带着不理想的上下文去生成，最终由 LLM 拒答。
**每一层判断都会累积误判概率** —— 这是 Agent 架构的固有代价。

**3. 延迟 2.9 倍是硬成本**

Agent 每题多 2-4 次 LLM 调用（分类 + 评分 + 可能的 2 次重写）。
在质量已接近天花板（Faithfulness 0.989 → 0.998）的情况下，
**这个代价是否值得取决于场景**：

- 追求**最低幻觉率**的场景（如医疗、法律问答）→ 值得
- 追求**响应速度**的场景（如交互式检索）→ 不值
- 追求**成本最优**的场景 → 需要看 token 消耗倍率

### 选型建议

| 场景 | 推荐 |
|---|---|
| 高吞吐、延迟敏感 | **基础 RAG**（0.97s vs 2.83s，质量差距很小） |
| 事实准确性优先 | **Agentic RAG**（幻觉率 2.17% vs 8.33%） |
| 需要工具能力（计算/元数据查询） | **必须 Agentic**（基础 RAG 无此能力） |

**一个务实的折中**：只在检索质量可能不佳时启用 Agent 链路 ——
比如先用基础 RAG 检索，若 top1 相似度低于某阈值再切换到 Agent 重试。
这能把 Agent 的成本花在真正需要的题目上。
