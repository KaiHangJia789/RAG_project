# RAG 检索增强生成：原理与架构

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是在大语言模型生成答案之前，先从外部知识库中检索相关文档片段，把检索结果作为上下文一并送入模型的技术方案。

它解决的核心问题是：大语言模型的参数化知识存在三个固有限制。第一，知识截止——模型训练完成后产生的新知识它一无所知。第二，无法溯源——模型给出的答案没有出处，用户无法验证。第三，幻觉——模型会用流畅自信的语气编造看似合理但完全错误的内容。RAG 通过"把事实来源外置"同时缓解这三个问题。

## 完整链路的五个阶段

一个生产级 RAG 系统包含五个阶段，每个阶段都有独立的优化空间：

1. **文档解析（Parsing）**：把 PDF、Markdown、Word 等格式转换为纯文本，同时保留结构信息（标题层级、表格、页码）。
2. **文本切分（Chunking）**：把长文档切成适合向量化的文本块。块太大则检索精度下降，块太小则语义不完整。
3. **向量化（Embedding）**：用嵌入模型把每个文本块转换为定长浮点向量。
4. **检索（Retrieval）**：把用户问题同样向量化，在向量空间中找最相似的 K 个文本块。
5. **生成（Generation）**：把检索到的文本块拼成上下文，连同问题一起送给大语言模型生成答案。

## 为什么不用微调

面对"让模型掌握私有知识"的需求，常见方案有两种：微调和 RAG。二者适用场景不同。

微调是把知识写进模型参数。优点是推理时没有额外延迟；缺点有三：成本高（需要标注数据和 GPU 训练）、更新慢（知识变更要重新训练）、无法溯源（本质上还是模型"记住"的，说不出出处）。微调更适合调整**风格和格式**，比如让模型输出特定 JSON 结构或模仿特定语气。

RAG 是把知识放在外部。优点是更新即时（改文档即可）、可溯源（能给出引用来源）、成本低（不需要训练）。缺点是推理延迟增加（多了一次检索和更长的上下文）。RAG 更适合**事实性问答**。

实践中两者常结合使用：用微调对齐输出格式，用 RAG 提供事实依据。

## 检索质量的三个关键指标

评估检索环节要用专门的指标，不能只看最终答案对不对。

**Context Precision（上下文精确率）**衡量检索结果的排序质量。它不只关心"有没有检索到相关文档"，还关心"相关文档是否排在前面"。计算公式是 rank-weighted average precision：对排序中的每个位置 k，计算前 k 个位置的精确率，再乘以该位置是否相关，求和后除以相关文档总数。

举例：假设检索返回 5 个片段，相关性依次为 [1, 0, 1, 0, 0]。位置 1 的精确率是 1/1 = 1，位置 3 的精确率是 2/3 ≈ 0.667。分子为 1×1 + 0 + 1×0.667 = 1.667，分母为相关文档总数 2，得到 Context Precision = 0.833。

**Faithfulness（忠实度）**衡量答案是否忠于检索到的上下文。做法是把答案拆解为若干条原子事实断言，逐条判断能否由上下文支持，得分等于被支持的断言数除以断言总数。

**Answer Relevance（答案相关性）**衡量答案是否切题。注意它与忠实度是正交的：一段完全忠实于上下文但答非所问的文字，忠实度满分而相关性为零。

## 什么情况下 RAG 会失败

理解失败模式比理解成功路径更重要。RAG 的典型失败模式有六种：

**检索没召回**：正确答案所在的文本块根本没被检索出来。原因可能是切分粒度不对、嵌入模型对领域词汇不敏感、或者问题表述与文档表述差异过大。

**检索召回了但排名靠后**：候选集里有正确文档，但被排到了 top_k 之外。这时增大 top_k 或引入重排序（rerank）模型可以改善。

**上下文里有答案但模型没用**：这种情况通常被称为"lost in the middle"——研究表明当上下文中相关信息位于中间位置时，模型的利用率显著低于位于开头或结尾时。对策是把最相关的片段放在上下文最前面。

**模型无视上下文、依赖自身知识作答**：这会产生幻觉。对策是在 prompt 中强硬约束"只使用上下文信息"，并在上下文不足时给出拒答路径。

**问题本身超出知识库范围**：知识库里根本没有答案。正确行为是拒答，而不是硬答。这需要相似度阈值来识别。

**切分破坏了语义完整性**：一个完整的概念被切断在两个块里，任一单独块都无法回答问题。对策是设置合理的块重叠（overlap）。

## 拒答机制的设计

拒答是 RAG 系统可信度的关键。设计要点在于把拒答判断放在**生成之前**，而不是指望模型自己说"我不知道"。

具体做法是设置相似度阈值：检索返回的候选结果中，如果最高相似度低于阈值，直接返回拒答，不调用大语言模型。这样做有两个好处：一是响应快（毫秒级而非数秒级），二是成本低（省掉一次昂贵的模型调用）。

阈值的选取不能拍脑袋。不同嵌入模型的余弦相似度分布差异很大，同一个阈值在 A 模型上过滤掉 10% 的噪声，在 B 模型上可能过滤掉 90% 的有效结果。正确做法是先用一批标注数据画出"可回答问题"与"不可回答问题"的相似度分布，取两条分布之间的谷底作为阈值。

除了阈值这一层，还需要第二层保险：在 prompt 里明确要求模型在上下文不足时输出指定的拒答语句。两层配合可以覆盖绝大多数情况。

## 引用溯源

引用溯源是 RAG 相对微调的核心优势，但它的实现比看起来复杂。

难点在于编号对齐。上下文里的片段被编号为 [1] [2] [3]，模型被告知引用时标注编号。但模型可能编造出 [7] 这种不存在的编号，也可能引用了编号但表述与原文不符。

工程上必须做校验：解析答案中所有 `[n]` 标记，检查 n 是否落在有效范围内。越界的标记应当从答案中剔除，同时记录越界率作为质量指标。这个检查是纯正则的，零成本，但能抓到其他手段抓不到的"编造引用"类幻觉。

引用要真正可用，还需要能定位回原文。这要求文本块在入库时保留来源信息（文件名、页码、块序号）。如果切分时丢失了页码，用户点击引用后只能定位到文档级，无法跳到具体位置。
